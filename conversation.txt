Code Analysis
The DQ SQL is structurally sound and executes successfully. It builds two CTEs: L3_TARGET_CUST aggregates distinct {{code:CUST_HCP_ID}} from the activity fact where {{code:PROD_BRAND_NM = 'KERENDIA'}}, field force in ('CR1','CR2','CR4','CR5'), and {{code:SEG_GRP_1_RPT_VAL IS NOT NULL}}; L2_TARGET_CUST aggregates distinct {{code:BAYER_CUST_HCP_ID}} from the targets dimension with identical brand/field-force/segment filters. The main query joins the two CTEs on {{code:FLD_FORCE_NM = FLD_FRC_ID}} and returns 'Fail' when {{code:SUM(L3_TGT_CNT) != SUM(L2_TGT_CNT)}}. The logic correctly implements a cardinality reconciliation check. The failure is NOT a SQL defect — the query runs, joins all four field forces, and correctly computes the sum difference. The root cause is the DATA mismatch revealed by the diagnostic rows: every field force has more HCPs in L3 than L2.
