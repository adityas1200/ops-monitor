=================================================
PRIMARY OBJECTIVE
=================================================

Transform RCA from a simple explanation into a fully explainable investigation report.

The RCA agent should behave like a senior production support engineer who documents:

- What failed
- Why it failed
- How it was investigated
- What evidence was collected
- What assets are impacted

The RCA agent should never guess.

Every RCA statement must be backed by evidence.

=================================================
ENHANCEMENT 1
EVIDENCE DRIVEN RCA
=================================================

Before generating RCA:

Collect evidence from all available systems.

For DQ failures:
- Failed DQ SQL
- DQ metadata
- Source counts
- Target counts
- Duplicate analysis
- Null analysis
- Integrity check results

For Snowflake Task failures:
- Task history
- Task dependencies
- Error messages
- Warehouse information

For Procedure failures:
- Query history
- Child queries
- Failed SQL statements
- Procedure execution logs

For AWS failures:
- Pipeline logs
- Stage failures
- Job failures
- Connectivity failures

Every RCA statement must contain evidence references.

Bad RCA:

"Source issue identified."

Good RCA:

"Target contains 18,234 fewer records than source.
Analysis shows records were dropped during REF_HCP join because 54 new source values are missing from reference mapping."

=================================================

AWS Failure
↓

↓
Procedure Failure
↓
Task Failure
↓
DQ Failure

Fault Propagation:
AWS Pipeline
→ Snowflake Procedure
→ Snowflake Task
→ DQ Failure

The RCA should identify both:

1. Actual Root Cause
